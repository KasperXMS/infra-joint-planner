# Harness v2 open issues

1. **Distributed durability is not fully validated.** File receipts assume one process per directory. Worker crash after an external side effect and before its success receipt remains indeterminate. A shared transactional receipt store, lease/fencing semantics, and actual network/power fault tests are future work. No exactly-once claim is made.
2. **No SDK conversation resume.** Failed or cancelled runs are marked interrupted, receipts are retained, and same-run directory recreation is denied. The project does not yet checkpoint agent conversation, budgets, formal plan, or pending tool calls for safe arbitrary restart.
3. **Formal bridge adoption is opt-in.** Old native runs are deliberately unchanged. A production Adapter experiment needs a new harness condition and explicit policy for when the Manager seals a terminal plan. The bridge does not infer missing semantic edges from free text; an open plan may never seal.
4. **Provenance can remain unknown.** Prompt text and unstructured Manager/Specialist exchanges cannot always be assigned exact producer IDs. Rewrites requiring that missing lineage are rejected. Artifact version/hash fields remain unknown when the Worker does not report them.
5. **Verifier savings remain unmeasured.** The four available historical traces contain no Verifier events. The fingerprint analyzer is offline only and its synthetic duplicate counts are not actual token/cost reductions. A live skip policy requires richer frozen traces and equivalence tests, especially for new evidence and final judgments.
6. **Feasibility is a contract, not a router.** `ActionFeasibilityProvider` has no live implementation, does not expose private infrastructure to baseline planners, and does not perform cost-aware routing or automatic semantic input reduction.
7. **No live large-model validation was run.** Unit and ASGI integration tests do not establish behavior under the prior 32K model-serving loads, real Worker processes, GPU OOM, or external artifact stores.
8. **Specialist adoption remains design-only.** A versioned policy and provenance contract exist, but the runtime deliberately rejects `explicit_specialist_adoption`; any live use needs a separately registered Harness condition and tests.
