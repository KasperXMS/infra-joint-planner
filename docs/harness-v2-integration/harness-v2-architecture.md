# Harness v2 architecture

Harness v2 retains the SDK-native Manager, Specialist, blind Verifier, operator registry, Physical Scheduler, and Worker. The formal workflow bridge is opt-in; historical experiment configurations do not enable it.

The Manager still chooses semantic tool calls. `NativeFormalWorkflowBridge.prepare()` records each accepted SDK tool call as a pending action in `OpenSemanticWorkflowPlan`, deriving edges only from declared artifact inputs and `depends_on`. A caller can add further fragments and seal a `SemanticWorkflowPlan` when it has an explicit Manager terminal model action and valid dependencies. No initial full DAG is required. Once sealed, changes go through the existing `apply_workflow_patch()` validator. `VersionedPendingWorkflow` checks the expected version, requires a quiescent frontier for KEEP/PATCH, locks completed/running actions, and commits plan and execution-state changes together. It does not choose a PATCH.

`WorkflowExecutionState` is separate from both plan and append-only trace. It records pending, reserved, running, completed, failed, indeterminate, and invalidated action IDs. `InformationProvenanceLedger` records declared/explicit/unknown source relations, artifact versions and available hashes, observations, Manager consumption, Specialist results, and prompt-input hashes. Unknown lineage blocks a rewrite that needs the missing independence proof. A text-similarity guess never becomes an edge.

`RuntimeActionGateway` reserves logical action IDs and writes controller receipts. Each physical child settles independently. The Worker accepts a scoped stable execution ID, writes a durable receipt before and after execution, and serves receipt lookup. On transport ambiguity the gateway queries the matching Worker receipt. It commits confirmed siblings and leaves unresolved side effects `indeterminate`; it does not replay them. `FileActionReceiptStore` uses per-run controller directories and a Worker-local directory. It assumes one process owns each directory; cross-process transactions and theoretical distributed exactly-once execution are unsupported.

`VerificationResult.complete` identifies one candidate action. The Harness binds its raw-output SHA256 and evidence-state version from the exact Verifier input, then checks ownership, success, the terminal output contract, and freshness. An unbound or stale complete verdict becomes `ready_for_synthesis`. The default terminal policy remains Manager-owned. `terminal-policy-v2` and `specialist-adoption-v1` define a separate explicit Specialist-adoption interface, but the runtime rejects that mode until separately implemented and preregistered. Specialist tool results carry typed success/failure/cancellation and real source IDs without invented terminal IDs.

Interrupted runs write a `run-recovery-v2` snapshot and remain non-resumable. The runner does not recreate a completed run directory, and the recovery contract rejects in-place SDK conversation resume. Old `run.failed` trace events remain emitted alongside `run.interrupted` for compatibility. The Worker and controller preserve artifacts and receipts for inspection.

Version markers: `action-receipt-v2`, `open-semantic-workflow-v2`, existing `semantic-workflow-v1` and `workflow-patch-v1`, `workflow-execution-state-v2`, `information-provenance-ledger-v2`, and `run-recovery-v2`. Existing trace records remain readable; new event types are additive.
