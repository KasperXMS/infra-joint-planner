# Harness findings, ranked by engineering risk

**Evidence notation:** `R` = deterministic offline reproduction in [focused tests](harness-focused-tests/test_architecture.py); `H` = historical report; `S` = source/test inspection only. A source difference is not automatically a defect. “Historical comparison changes” means a behavior-changing fix creates a new experimental condition; it never licenses rewriting frozen scores.

## H-01 · P1 · A — partial success is not committed after a sibling's exception (`R`)

1. **InfraMAS:** [`RuntimeActionGateway.execute_batch`](../../src/infra_joint/control/gateway.py#L47-L82) reserves IDs, uses `asyncio.gather`, and calls `_complete` only after every action and post-observation return; [`SemanticActionValidator`](../../src/infra_joint/control/validation.py#L97-L113) knows only completed successes. Native and formal loops both use this gateway.
2. **Comparator:** [OpenCode step settlement](https://github.com/anomalyco/opencode/blob/c1615b1db9c2e7a955f2be1024e84bb74c90cc6b/packages/core/src/session/runner/step.ts#L144-L235) classifies per-tool exits and emits missing/interrupted outcomes; [OpenHands batch](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/agent/agent.py#L270-L412) emits per-action events. Neither comparison alone implies external exactly-once.
3. **Difference:** a successful sibling's artifact/effect may exist even though the gateway leaves its artifact unknown and its action ID reserved when another sibling raises unexpectedly.
4. **Why:** state and side effect diverge; a retry using the same action ID is rejected, while a new ID risks duplicate side effects. This is an atomicity/reconciliation defect, separate from a legitimate typed tool failure.
5. **Counterexample:** `test_parallel_gateway_exception_loses_successful_sibling_commit` uses the real `PhysicalExecutionService` branch with a deterministic success-before-exception barrier; the effect exists, `known_artifacts` omits it, and same-ID retry fails. Historical incidence **not established**; no raw trace is claimed.
6. **Impact:** possible task failure, contaminated resource accounting, and unsafe future checkpoint/replay after rare transport/cancellation faults; ordinary model wrong answers are unrelated.
7. **Minimal patch design:** settle all started children with per-action outcomes/exception metadata, persist/commit completed successes before propagating system error, and reconcile indeterminate children against idempotency keys/artifact hashes. Cover failure of the post-execution infrastructure observation as well. Do not silently convert uncertain remote completion to a clean failure.
8. **Regression:** success+typed failure; success+unexpected exception; cancel during batch; post-observe failure; same-ID retry after definite completion; unknown remote completion remains explicitly indeterminate.
9. **Historical comparison:** yes for any new run that exercises an interrupted batch; retain old traces and label new gateway version.

## H-02 · P1 · A/B — Verifier `complete` is not bound to the candidate returned (`R`)

1. **InfraMAS:** [`VerificationResult`](../../src/infra_joint/control/verification.py#L21-L41) has no `candidate_action_id`; [`after_batch`](../../src/infra_joint/control/native_agents.py#L689-L713) chooses `_latest_terminal_candidate` regardless of which candidate the Verifier assessed. [Verifier instructions](../../src/infra_joint/control/verification.py#L132-L157) require *a* successful Manager candidate, not specifically the latest.
2. **Comparator:** SDK's [tool-use callback](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/run_internal/turn_resolution.py#L753-L781) can select a concrete tool result; [Microsoft message aggregation](https://github.com/microsoft/agent-framework/blob/dc649e5980d42cef5310e2d1cef40f4599324f44/python/packages/orchestrations/agent_framework_orchestrations/_concurrent.py#L84-L162) keeps participant response items before aggregation.
3. **Difference:** InfraMAS approves an unaddressed semantic verdict, then returns the last valid-format Manager model answer.
4. **Why:** two candidate outputs in one batch can differ. A verdict referring to the first does not establish correctness of the second. The final output contract checks format and provenance, not semantic equality to the approved candidate.
5. **Counterexample:** `test_verifier_complete_has_no_candidate_binding_and_selects_latest` presents `A` then `B`; a `complete` reason explicitly names first `A`, but final answer and terminal action are second `B`. This proves a contract gap; no claim that a production LLM actually made that exact verdict.
6. **Impact:** possible task-success misclassification and unverifiable answer provenance in batched/multiple candidate turns; not every historical `complete` is affected.
7. **Minimal patch design:** include mandatory `candidate_action_id` for `complete`, expose bounded candidate IDs to Verifier, validate ownership/success/output contract, and return exactly that candidate. If multiple candidates are possible and ID is missing, fail closed or request clarification within the existing budget.
8. **Regression:** two conflicting candidates, stale ID, specialist-owned ID, failed candidate, format-invalid candidate, single candidate, parallel result order.
9. **Historical comparison:** yes where candidate selection differs; preserve prior scores and annotate affected traces if identifiable.

## H-03 · P1 · B/F — specialist result cannot satisfy terminal ownership (`H`, `S`)

1. **InfraMAS:** [`_specialist_tool`](../../src/infra_joint/control/native_agents.py#L543-L678) returns child text/artifact IDs; [`_terminal_source`](../../src/infra_joint/control/native_agents.py#L1340-L1366) and [`_latest_terminal_candidate`](../../src/infra_joint/control/native_agents.py#L1690-L1704) require a successful **Manager-owned** `LogicalModelAction`.
2. **Comparator:** SDK [`Agent.as_tool`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/agent.py#L599-L605) returns nested output to the original agent; SDK terminal policy may accept a tool result or plain final, so the ownership rule is InfraMAS-specific.
3. **Difference:** a specialist's completed synthesis is evidence for the Manager but can never directly supply final provenance, even when the blind Verifier says `complete`.
4. **Why:** the rule preserves final Manager responsibility and benchmark provenance, yet may consume another model call/turn and can make an otherwise solved task fail when the Manager cannot produce its own successful candidate.
5. **Evidence:** [`test_complete_verdict_without_model_candidate_fails_closed`](../../tests/test_native_agents.py#L1727-L1753) encodes the intended behavior. [Historical multiscale report](../multiscale-planner-results-v1.md#L261) describes B0 task 4: specialist success and Verifier complete followed by rejection for absent Manager candidate. This is a documented **constraint**, not an accidental SDK failure.
6. **Impact:** measured completion and cloud/local model calls may reflect this contract. Exact avoidable-call count needs trace-level counterfactual replay; this audit does not invent one.
7. **Minimal patch design:** first choose and preregister policy. If research permits delegation as final evidence, accept a typed specialist-produced terminal candidate with immutable source action ID and Manager explicit adoption; if not, keep rule and ensure Verifier cannot say `complete` before a Manager candidate exists. The latter is the smallest consistency correction under the current protocol.
8. **Regression:** specialist success with/without materialized output, Manager explicit adoption, invalid specialist output, Verifier readiness, owner and source ID checks.
9. **Historical comparison:** yes if terminal policy changes; treat as a new harness condition. Tightening impossible `complete` to `ready` can also change recovery path and should be versioned.

## H-04 · P2 · C/D — every nonempty Manager tool batch can incur full cumulative semantic verification (`S`)

1. **InfraMAS:** [`after_batch`](../../src/infra_joint/control/native_agents.py#L689-L714) calls Verifier after any nonempty result batch; [`_verify_manager_batch`](../../src/infra_joint/control/native_agents.py#L725-L878) serializes all accumulated actions/observations each time. Schema/phase/visibility failures may still yield a tool result. Verifier call budget is independent.
2. **Comparator:** SDK [tool-use behavior](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/run_internal/turn_resolution.py#L753-L781) is optional; OpenCode [step tool error settlement](https://github.com/anomalyco/opencode/blob/c1615b1db9c2e7a955f2be1024e84bb74c90cc6b/packages/core/src/session/runner/step.ts#L209-L235) returns deterministic tool failures without a mandatory independent LLM.
3. **Difference:** InfraMAS pays a semantic Verifier on each Manager batch, including some batches with no new semantic evidence, while deterministic schema/phase checks are already performed in code.
4. **Why:** repeated cumulative context raises token cost and can consume Verifier budget before a useful candidate. The Verifier is **not merely duplicating schema validation**: its evidence sufficiency and semantic correctness judgment is a distinct research role.
5. **Evidence:** source call path; historical [multiscale report](../multiscale-planner-results-v1.md#L241-L253) records repeated ready/schema/phase interactions. Exact monetary savings are **Not Verified** without request-level costs and a counterfactual policy.
6. **Impact:** avoidable Verifier calls/tokens, delayed feedback, possible budget exhaustion; semantic error detection value must be retained.
7. **Minimal patch design:** compute a semantic-state fingerprint and skip the LLM when only a deterministic rejected call occurred or the evidence/candidate state has not changed; return typed validation feedback directly. Invoke semantic Verifier after meaningful new observation or candidate, with periodic/terminal safeguards. Log skipped-call reason and compare blind-verdict equivalence before adoption.
8. **Regression:** invalid schema, phase rejection, repeated same call, new evidence, competing candidate, changed artifact, terminal attempt, budget accounting, verifier blindness.
9. **Historical comparison:** yes: altered call policy and costs constitute a new harness condition; never backfill speculative savings into prior experiments.

## H-05 · P2 · D/B — nested Agent failure can masquerade as a successful specialist answer (`R` + `S`)

1. **InfraMAS:** [`_specialist_tool`](../../src/infra_joint/control/native_agents.py#L636-L672) accepts any string returned by SDK wrapper as `answer`, emits `SubagentResult` with no success/failure field, and if no child action exists invents `subagent:<id>` terminal ID.
2. **Comparator:** SDK v0.20.0 [`Agent.as_tool`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/agent.py#L592-L605) defaults to [`default_tool_error_function`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/tool.py#L1863-L1872), which converts nested errors into ordinary text to help parent recovery.
3. **Difference:** SDK's model-facing recovery string lacks a typed success bit at InfraMAS's application boundary; the wrapper records it as an ordinary completed specialist result.
4. **Why:** a parent can still read the error text, but traces and analysis can misattribute a failed child as completed; the synthetic terminal ID is not an executed action. This is an InfraMAS interpretation gap, not an SDK defect.
5. **Evidence:** installed-SDK test `test_installed_sdk_agent_tool_failure_is_plain_text` makes nested `Runner.run` raise and observes a plain string. The subsequent InfraMAS wrapper branch is source-proven; an end-to-end native Runner failure trace is **Not Verified**.
6. **Impact:** failure taxonomy, recovery attribution and provenance; potential capability loss if Manager treats the textual error as evidence.
7. **Minimal patch design:** use an explicit typed nested-run result/error channel or configure `failure_error_function=None` and catch/serialize typed failure in InfraMAS; keep model-facing recovery text but mark child status failed and avoid invented action provenance.
8. **Regression:** nested max-turn/error/cancel; malformed child arguments; genuine empty answer; last child action failed; parent recovery on typed failure.
9. **Historical comparison:** potentially yes for failure-type rates and any parent behavior altered by feedback; raw old outputs remain unchanged.

## H-06 · P1 for Adapter, P3 for current pilots · E/D — execution graph omits implicit information flow (`R`)

1. **InfraMAS:** [`ExecutionGrownGraph.add`](../../src/infra_joint/control/graph.py#L34-L60) adds explicit action dependencies and declared artifact input producer edges only. [`WorkflowTraceRecorder`](../../src/infra_joint/workflow/trace.py#L1-L36) records chronological events, not all semantic read edges.
2. **Comparator:** LangGraph [pending writes/checkpoints](https://github.com/langchain-ai/langgraph/blob/afbe7e48b17f62e139b5c6337ab934549e6dc73b/libs/langgraph/langgraph/pregel/_loop.py#L544-L565) and Microsoft [message supersteps](https://github.com/microsoft/agent-framework/blob/dc649e5980d42cef5310e2d1cef40f4599324f44/python/packages/core/agent_framework/_workflows/_runner.py#L108-L186) make explicit graph/message state. Neither automatically discovers information copied into prompt text.
3. **Difference:** a Manager can copy a previous observation or specialist text into a later model prompt without declaring the produced artifact ID; the execution graph then contains no causal edge.
4. **Why:** this graph is a truthful *declared execution* graph, but cannot alone validate reordering/rewriting that assumes complete logical lineage. It may underattribute transfer/model cost to upstream evidence.
5. **Counterexample:** `test_execution_graph_omits_inline_observation_dependency` constructs a later model prompt using an inline excerpt from a previous result without an input artifact ID; no edge appears. The prompt lineage is explicitly constructed in the test; production frequency **Not Verified**.
6. **Impact:** future Adapter safety and provenance/cost attribution. Current gateway correctly validates declared artifact dependencies, so omission does **not** by itself prove an invalid current execution.
7. **Minimal patch design:** add a separate information-dependency ledger for model/tool-result consumption and specialist handoff, with source event/action/artifact IDs and uncertainty markers for unstructured text; require explicit dependencies for any patchable future plan. Never infer reliable lineage solely from string matching.
8. **Regression:** inline observation, specialist text, artifact ID, multiple versions, unknown provenance, authorized reordering only when all declared dependencies preserved.
9. **Historical comparison:** graph/provenance schema changes; old scores remain valid as scores but old graphs cannot be treated as complete rewrite proofs.

## H-07 · P1 for resumable Adapter, P3 for current finite pilots · E — native and formal runners lack integrated durable resume (`S`)

1. **InfraMAS:** fresh `_NativeState` each [`run`](../../src/infra_joint/control/native_agents.py#L348-L415); no SDK `session` or `RunState` argument is supplied. [`AdaptiveWorkflowExecutor.execute`](../../src/infra_joint/control/adaptive_executor.py#L91-L105) also initializes fresh runtime state. Trace and artifact store persist evidence but have no transactionally restoring runner.
2. **Comparator:** SDK v0.20.0 [`Agent.as_tool`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/agent.py#L943-L958) can accept a session; LangGraph [resume requires checkpointer](https://github.com/langchain-ai/langgraph/blob/afbe7e48b17f62e139b5c6337ab934549e6dc73b/libs/langgraph/langgraph/pregel/_loop.py#L991-L997); Microsoft [graph signature](https://github.com/microsoft/agent-framework/blob/dc649e5980d42cef5310e2d1cef40f4599324f44/python/packages/core/agent_framework/_workflows/_runner.py#L322-L335) protects restore against incompatible topology.
3. **Difference:** InfraMAS persists trace/artifacts, not full SDK conversation + logical partitions + in-flight action outcomes.
4. **Why:** crash recovery from an interrupted physical call cannot safely infer whether to rerun, adopt or reject an effect. This is a missing feature for long-lived adaptive workflows, not proof of failure in completed short runs.
5. **Evidence:** source entry/trace APIs and existing tests; a production crash/replay reproduction is **Not Verified**.
6. **Impact:** Adapter experiments with long tasks may lose work or risk duplicate side effects; current finite pilots can continue under an explicit no-resume protocol.
7. **Minimal patch design:** versioned checkpoint at action-boundary with SDK state, formal partition, graph/validator reservations, artifact manifest, budget counters and in-flight IDs; reconcile effects before replay. Do not assume SDK session or event log alone supplies exactly-once execution.
8. **Regression:** crash before/after reservation, after remote effect before observation, completed prefix on restore, schema version mismatch, retry idempotency and budget continuity.
9. **Historical comparison:** future resume-enabled runs have a new protocol; no retroactive score changes.

## H-08 · P2 · B/D — static capability information does not predict artifact-specific physical context fit (`H`, `S`)

1. **InfraMAS:** [`build_static_capability_contract`](../../src/infra_joint/control/capabilities.py#L18-L82) supplies anonymous model-class context/modality limits at task start; [`_manager_input`](../../src/infra_joint/control/native_agents.py#L1325-L1337) includes them. The Scheduler/resolver uses live availability and action inputs ([`physical.py`](../../src/infra_joint/control/physical.py#L135-L210)). Optional predecision profiles are injected only when `predecision_profiles` is enabled ([`native_agents.py`](../../src/infra_joint/control/native_agents.py#L403-L480)).
2. **Comparator:** OpenCode [prepares context before a provider step and compacts on overflow](https://github.com/anomalyco/opencode/blob/c1615b1db9c2e7a955f2be1024e84bb74c90cc6b/packages/core/src/session/runner/llm.ts#L198-L267); OpenHands [resolves route metadata before condensation](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/agent/agent.py#L739-L756).
3. **Difference:** an anonymous static limit tells the Planner what *could* fit, but not whether this proposed prompt plus referenced artifact bundle fits any currently available deployment. Physical rejection arrives after the action is attempted.
4. **Why:** the Planner may spend repeated turns constructing requests guaranteed to fail the current conservative envelope. This is partly a deliberate blindness/privacy tradeoff, not an invitation to expose deployment IDs.
5. **Evidence:** [historical multiscale report](../multiscale-planner-results-v1.md#L261-L265) records repeated physical context rejects; source shows a typed `context_limit_exceeded` path. The `estimated_input` can use bytes/image proxy, **not actual tokenizer tokens**; exact false-rejection frequency is **Not Verified**.
6. **Impact:** avoidable physical selection attempts and Manager/Verifier turns, possible capability loss under limited budgets; no proof that a rejected request would have fit a real model.
7. **Minimal patch design:** expose a resource-blind per-action *feasibility query* or safe size-envelope diagnostic before submission, with candidate count/range, confidence and a reduction suggestion; keep Scheduler authoritative and distinguish conservative estimate from measured token count.
8. **Regression:** boundary artifact sizes, image/video modalities, zero candidates, dynamically unavailable deployment, anonymity, conservative unknown estimate, no silent truncation.
9. **Historical comparison:** yes if this changes Planner-visible information or call sequence; analyze as a new condition.

### Controls and non-findings

The Manager's inability to select physical deployment and the Verifier's blindness to resource identities are **F deliberate research constraints**, consistent with logical/physical role isolation. The finite operator catalog, turn/request budgets and fail-closed terminal format are also defensible. The raw schema validator is optional in the runtime constructor but explicitly enabled in inspected v1/v2 lightweight pilots and multiscale script (`validate_raw_tool_calls=True`); do not describe their historical schema errors as a disabled-validator defect. Provider-side function-call parsing can fail before InfraMAS receives a raw call and should remain a separate failure category. Failed output IDs staying reserved prevents conflicting producer identities and is not independently classified as a bug. Static source review found no evidence that every high Verifier count, score-zero cell or malformed model tool call is harness-caused.
