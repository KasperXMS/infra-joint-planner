Read depth is intentionally unequal: the SDK's deployed tag, OpenCode step loop, Codex Rust tool loop and OpenHands conversation/event semantics received the deepest tracing; LangGraph and Microsoft were targeted to revision/checkpoint questions. No upstream test suite was run, so claims above are source/test-inspection claims, not cross-project performance comparisons.

Additional boundary checks: Agents SDK guardrails are configured on [`Agent`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/agent.py#L350-L355), while InfraMAS uses custom raw schema/semantic validation in its FunctionTool callbacks; SDK `RunHooks` are present, but most native handoff/tool hooks are no-ops beyond model timing. OpenHands distinguishes a [local workspace](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/workspace/local.py#L17-L47) from a [remote workspace runtime](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/workspace/remote/base.py#L133-L164); use of that abstraction is not itself proof that every tool is sandboxed. Codex's parallel gate explicitly distinguishes parallel-safe from exclusive tools, whereas InfraMAS's physical gateway relies on domain validation plus `gather`; the observed partial-settlement defect is within the latter, not a claim that the SDK serializes tools.

The decisive terminal paths are concrete. In SDK v0.20.0 [`check_for_final_output_from_tools`](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/run_internal/turn_resolution.py#L753-L781), the default is `run_llm_again`; a custom callback can nominate a tool result for final output. The same resolver accepts a plain message as final when no further work is needed ([lines 1076–1098](https://github.com/openai/openai-agents-python/blob/d2bda3f3110415bf02e526a3983b0d0fa903e0d7/src/agents/run_internal/turn_resolution.py#L1076-L1098)). InfraMAS uses that callback to request blind verification and then imposes its own Manager-owned physical `invoke_model` provenance. This distinction is why H-03 is classified as an application research constraint. `Agent.as_tool` accepts an optional nested session, but InfraMAS passes no session into its native Manager run and no durable external-effect transaction follows from SDK RunState alone.

In OpenCode, tool fibers are joined and abnormal exits are classified before a step can return `Completed`, `Retry`, `Continue` or `Compacted` ([`step.ts` 144–287](https://github.com/anomalyco/opencode/blob/c1615b1db9c2e7a955f2be1024e84bb74c90cc6b/packages/core/src/session/runner/step.ts#L144-L287)); each settled tool is published into session history. A foreground subagent blocks on a child session job and preserves the child session ID on error ([`subagent.ts` 220–265](https://github.com/anomalyco/opencode/blob/c1615b1db9c2e7a955f2be1024e84bb74c90cc6b/packages/core/src/tool/plugin/subagent.ts#L220-L265)). Codex `run_turn` handles each response item, queues its tool future, then uses `needs_follow_up` for the next sample ([`turn.rs` 2780–2829](https://github.com/openai/codex/blob/90f00bd89ed3263b4d5993849cccb795f4330449/codex-rs/core/src/session/turn.rs#L2780-L2829)); the tool runtime encodes ordinary errors with the original call ID and `success=false` ([`parallel.rs` 333–363](https://github.com/openai/codex/blob/90f00bd89ed3263b4d5993849cccb795f4330449/codex-rs/core/src/tools/parallel.rs#L333-L363)). Its `compact_resume_fork` and `tool_parallelism` tests exercise those paths with mock providers. These are examples of explicit result identity and persistence, not proof that a general agent framework solves InfraMAS domain idempotency.

OpenHands [`_ActionBatch.prepare/aprepare`](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/agent/agent.py#L270-L350) maps executor results back to action IDs, [`emit`](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/agent/agent.py#L352-L379) emits in original order, and `finalize` applies FinishTool only after that batch ([lines 381–412](https://github.com/OpenHands/software-agent-sdk/blob/7bd668c9ab74f62c85745cd95adb503f53e7228b/openhands-sdk/openhands/sdk/agent/agent.py#L381-L412)). Its event log and conversation serialization tests verify persistence, while tool-call recovery tests verify parsing and corrective model feedback. A parallel executor can still need special care for partial external effects; the audit uses this source to compare event/result structure, not to assert perfect atomicity.
