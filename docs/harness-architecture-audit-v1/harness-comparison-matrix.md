# Source-level comparison matrix

Keys: **N** native runtime behavior, **O** optional facility, **A** application logic, **—** not established in the inspected path. Exact pinned SHAs, source permalinks and test references are in [the source review](opensource-harness-source-review.md). The table compares *mechanisms*, not framework quality or benchmark performance.

| Dimension | InfraMAS current | Agents SDK v0.20.0 | OpenCode / Codex CLI | OpenHands SDK | LangGraph / Microsoft AF |
|---|---|---|---|---|---|
| Agent loop | SDK Manager with custom FunctionTools and post-batch Verifier; bounded turns (**A+N**) | Model/tool/result/repeat, plain final (**N**) | Session sampling loops and tool continuations (**A**) | Conversation step and explicit FinishTool (**N**) | Pregel/superstep workflow runners (**N**) |
| Tool interface | Outer `inputs`+`arguments`, optional raw JSON Schema, semantic validator (**A**) | FunctionTool strict schema/error callback (**N**) | Tool routers + application permissions/admission (**A**) | Typed action/observation events (**N**) | Node/executor message contracts (**N**) |
| Subagent / handoff | Bounded Agent-as-Tool, text plus produced artifact IDs; Manager stays owner (**A+N**) | Agent-as-Tool returns text; handoff transfers owner (**N**) | Child session ID/resume; Codex collaboration controls (**A**) | Conversation/agent composition (**A**) | Handoff orchestration and subgraphs (**O/N**) |
| Terminal | Manager-owned successful `invoke_model` + contract + Verifier complete (**A**) | Plain final or configured tool result; no model tool required (**N**) | Session step completion/stop hooks (**A**) | FinishTool, truncate later calls (**N**) | Convergence/END and optional custom termination (**N/O**) |
| State | `_NativeState` per run, action graph and trace; formal plan separate (**A**) | Runner state, optional sessions/RunState (**N/O**) | Persistent session/history, child jobs; Codex thread/history (**A**) | Conversation events/state (**N**) | Checkpointed graph state/supersteps when enabled (**O**) |
| Context compaction | No native-loop compaction configured or evidence-retention policy (**—**) | SDK integration may use session/context processors but unused here (**O**) | Explicit compaction and history replacement (**A**) | Condenser/condensation event (**N/O**) | State updates/checkpoints, not automatic natural-language compaction (**N/O**) |
| Error recovery | Typed semantic/physical failures; nested SDK exception can become ordinary text (**A+N**) | Tool failure formatter, next turn (**N**) | Typed tool events, interrupted/unfinished settlement (**A**) | AgentErrorEvent; pending-action recovery (**N**) | Resume/replay pending graph tasks; no external exactly-once guarantee (**O**) |
| Verifier | Blind LLM after every nonempty Manager tool batch; cumulative context (**A**) | Optional guardrails/hooks, no built-in equivalent mandatory semantic Verifier (**O**) | Policy/hooks and application tests, no identical gate (**A**) | Security/refinement policy, no identical gate (**A**) | User nodes/conditions can implement verification (**A**) |
| Workflow modification | Native graph append-only; separate Formal KEEP/PATCH pending revision (**A**) | Dynamic tools/agents, no semantic graph patch (**N**) | Open-ended next tool, not versioned semantic DAG (**A**) | Next actions from model; event state (**N**) | Mutable state with graph topology typically fixed per compiled run; workflow builder topology fixed (**N**) |
| Artifact provenance | Explicit input/output producer edges, namespaced artifact IDs; inline info untracked (**A**) | Tool items/call IDs but no domain artifact lineage (**N**) | Session/tool events and file snapshots (**A**) | Event IDs and observations (**N**) | State/channel writes/messages, application-defined artifact semantics (**N+A**) |
| Parallel execution | SDK tool calls may overlap; gateway `gather` lacks partial-success settlement on exception (**A**) | Multiple tool results collected in model step (**N**) | Codex parallel-safe read lock vs exclusive write lock; OpenCode fibers (**A**) | Parallel action executor with ordered event emission (**N**) | Pregel task / participant superstep concurrency (**N**) |
| Checkpoint / resume | Native loop has trace but no integrated state restore; formal executor likewise fresh-start per call (**—**) | Optional sessions and RunState; external action atomicity outside SDK (**O**) | Persistent session/rollout with resume tests (**A**) | Event/state serialization and reload (**N**) | Optional checkpointers, graph signature validation in Microsoft (**O**) |
| Observability / cost | Logical trace/physical telemetry and model usage; verifier input repeats cumulative context; unknown GPU price remains unknown (**A**) | Usage/hooks/tracing (**N/O**) | Step/tool wait and execution timing; session usage (**A**) | Event stream/tool IDs (**N**) | Checkpoint/step events; custom domain cost required (**N+A**) |

An SDK-native open-ended **next-call loop** exists in InfraMAS. The stronger claim that its execution-grown graph is an editable future workflow is false: graph nodes are added as calls arrive, and Formal KEEP/PATCH belongs to a different runtime. Conversely the project already has a validated formal pending-plan engine, so “no workflow adaptation support anywhere” would also be false.
