# Research implications and Go/No-Go

This audit changes **interpretation**, not frozen data. Historical 18-cell, 42-cell, granularity and multiscale results remain the results of their registered Harness/serving conditions. No held-out score, TSR significance, GPU monetary price or counterfactual cost is inferred here.

**Q1 — Determinate failures explaining earlier task failure?** Yes, one documented historical B0 t4 failure is directly explained by the deliberate Manager-owned terminal contract: Specialist succeeded and Verifier returned `complete`, but the Manager had no successful model candidate ([historical report](../multiscale-planner-results-v1.md#L261); [current source](../../src/infra_joint/control/native_agents.py#L1690-L1704)). H-01 and H-02 are deterministic correctness gaps, but their occurrence in prior raw cells is **not verified**. The [granularity failure report](../skill-granularity-failure-analysis-v1.md#L18-L40) instead attributes several other failures to legitimate context preflight, provider queue timeout, model schema errors, budgets and answers. A successful legal terminal answer may still be evaluator-wrong.

**Q2 — Which limits are InfraMAS rather than model/SDK?** Manager-owned model terminal, blind Verifier after each nonempty tool batch, finite action catalog, artifact visibility, phase machine, budget, physical role isolation, append-only native action graph and lack of native-loop resume are application choices. Agents SDK v0.20.0 permits plain final or configured tool-result final and offers optional session/run-state facilities. Provider parsing failures before a raw function call and model-generated malformed arguments are distinct from these policies.

**Q3 — Avoidable calls?** Deterministic rejected calls need actionable typed feedback, not a new semantic Verifier on unchanged evidence; repeated cumulative Verifier inputs can be skipped only after a measured equivalence test. In no-Manager-candidate states, a `complete` verdict cannot satisfy current terminal contract and should become `ready_for_synthesis` without encouraging another evidence-expansion loop. A successful Specialist may require a second Manager synthesis call under the current policy. The audit does **not** claim exact call or USD savings without per-request replay.

**Q4 — Open-ended planning or only execution?** The Manager has an open-ended SDK loop that may choose the next allowed tool, delegate, inspect feedback and revise *its next action*. The native graph is created as actions execute; there is no explicit, editable proposed future plan in that path. Thus it supports open-ended **sequential tool choice and local planning**, but not validated online revision of a future logical workflow. The separate formal executor does hold pending actions and legal KEEP/PATCH; it has not been unified with native Manager state.

**Q5 — Is the current graph an Adapter modification target?** Not the execution-grown graph alone: it is append-only history and its edges omit inline observation/child-text flows. The formal `SemanticWorkflowPlan` pending suffix is the appropriate target, provided the Adapter has complete declared dependencies, versioned immutable prefix and boundary reconciliation. Chronological trace parent links are audit order, not substitute DAG edges.

**Q6 — Required before Adapter experiments?** Fix H-01 partial-success settlement; bind Verifier completion to a concrete candidate and type Specialist errors; preregister terminal delegation policy; bridge native proposals to the existing formal pending-plan validator with explicit information provenance; define crash/no-resume policy and action reconciliation. A cost-efficiency claim also needs measured Verifier scheduling and complete resource accounting. These are minimal ordered repairs, not a new agent framework.

**Q7 — Constraints to retain?** Keep private evaluator/gold isolation, task/evaluator freezing, semantic-vs-physical decision separation, blind semantic Verifier, physical feasibility in Scheduler, declared finite operator contracts, context fail-closed, request/turn limits, artifact namespaces, immutable completed/running prefix and honest unknown GPU price. They protect research validity. A future experimental policy may loosen Manager terminal ownership, but only as a preregistered new condition.

**Decision:** No-Go for claiming rigorous Infrastructure-aware Logical Workflow Adaptation on the *current native graph*. Go for a narrowly scoped Harness v2 repair using the existing Formal KEEP/PATCH machinery after the acceptance tests in [the design proposal](harness-v2-design-proposal.md) pass. Existing completed benchmark results remain valid observations of their exact harness conditions; they should not be relabeled as pure Planner capability measurements when a harness-induced terminal or failure-attribution condition contributed. H-01/H-02 historical incidence, raw-trace-wide savings, exact cost deltas and full crash recovery remain **Hypothesis / Not Verified** until separately measured.
