# UNKNOWN failure attribution

The five completed historical H1 model calls all returned `UNKNOWN` and scored zero. The available evidence rules out a complete loss of the MultiHop supporting articles and silent input truncation as explanations for those completed calls. It does **not** establish one unique cause for the model's abstention.

The offline auditor rebuilt the exact final prompt from immutable source archives and the frozen trial code. Its tokenizer counts exactly matched all five historical `context_tokens` values: 9,692, 25,175, 27,469, 2,802 and 2,876. The different `prompt_tokens` values reported by Ollama include chat-template overhead. Both annotated support documents, including their full stored bodies, were in each MultiHop G0 prompt and the reconstructed G1 evidence. The first MultiHop G1 trial failed at HTTP 413 before any model request, so its reconstructed 29,175-token prompt is a counterfactual audit, not an observed call.

The MMQA final evidence selected only one of two annotated support document IDs in either workflow; this is a confirmed retrieval miss. Its 24-row table and four headers survived. G1 MultiHop retained only shard-level IDs in historical selected records, obscuring article-level traceability. G0 searched publishers named in the question while G1 searched whole source shards, so their scopes were not matched. These defects complicate causal comparison; they do not explain why MultiHop G0 abstained despite both support articles being present.

Three synthetic, nonbenchmark probes returned the correct ordinary answer, including `think=true`; the endpoint and parser were functional. Eight preregistered task-level replay diagnostics under grounded and reasoning conditions yielded zero correct answers: four `UNKNOWN`, two wrong substantive answers, and two reasoning-budget length stops without final answers. This supports a task-level evidence-interpretation/model-capability limitation under the tested conditions. Verbose JSON rendering, irrelevant evidence, the conservative instruction, and insufficient output budget remain plausible contributors, but the fixed budget does not isolate their individual effects. No gold answer or oracle support list entered a model request.

The earlier 91,164-byte G1 artifact read against a 65,536-byte cap was a separate execution-contract failure. It was already repaired to a bounded 262,144-byte study Worker setting before the historical replacement pair; that pair still scored zero. Historical outcomes remain unchanged.
