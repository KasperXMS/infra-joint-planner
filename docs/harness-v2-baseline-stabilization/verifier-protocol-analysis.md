# Verifier protocol and bounded recovery

**Trace-supported observation.** All 11 raw-schema failures have the same violating field: `evidence_state_version` is a JSON string. The raw `VerificationResult` schema requires integer or null. JSON parsing and tool-name matching succeeded for all 11. Nine responses declared `complete`; Pydantic would coerce their version strings, but the frozen strict raw-schema wrapper rejected them correctly. Two declared `continue` while including candidate bindings; they fail both raw schema and semantic model validation. The twelfth Verifier failure is raw-schema-valid but semantically invalid. Accepting any of these by silent coercion would weaken the pre-registered protocol.

The source path is `VerificationResult` and `OpenAIAgentsBlindVerifier` in `src/infra_joint/control/verification.py:22-52,142-239`, the raw-schema wrapper in `src/infra_joint/experiments/pilot_safety.py:87-126`, and `_verify_manager_batch` in `src/infra_joint/control/native_agents.py:774-935`. The frozen Verifier uses `tool_use_behavior="stop_on_first_tool"` and `Runner.run(..., max_turns=1)`. The wrapper returns a typed `schema_validation_failed` tool output, but the SDK stops on that first tool result; subsequent `VerificationResult` parsing fails and native runtime records a fatal loop error. The installed experiment SDK was `openai-agents==0.20.0`; its `agents/models/chatcmpl_converter.py:222-230` passes function arguments onward without the type conversion seen in these failures, and `agents/agent.py:373-392` documents first-tool stopping. Provider-side corruption was **not verified**; the saved raw API responses themselves already contain the string field.

**Reproduced defect / opt-in fix.** `BoundedProtocolVerifier` in `src/infra_joint/control/verifier_stabilization.py` uses the same resource-blind semantic instructions, same tool schema and same model settings, but validates raw JSON Schema before Pydantic semantics. It returns `schema_validation_failed` or `semantic_validation_failed` to the independent Verifier and allows one corrective SDK turn, with a hard maximum of two provider attempts. A second invalid verdict remains a failure. Deterministic tests use the real installed Agents SDK with a scripted model: raw-invalid→valid, semantic-invalid→valid, and two-invalid→stop. This changes provider-call budget and potential answer trajectory; it is a separate, unrun v2.1 condition, never a retrospective H1 correction.

**Reproduced defect / separate opt-in fix.** `TerminalContractVerifier` applies the native runtime's exact deterministic terminal parser to a candidate that the independent Verifier has already marked `complete`. If that parser rejects it, the wrapper returns `ready_for_synthesis` with the original token counts, so the Manager can use its existing remaining synthesis budget. It does not decide evidence sufficiency, alter task answers, or see physical-resource state. The original mismatch arose because `_leading_declared_choice` in `native_agents.py:1867` accepted a leading label plus whitespace while `_deterministic_terminal_answer` at `native_agents.py:1831` rejected it. This is a separate v2.1 condition with no extra Verifier provider request.

Typed parsing with bounded recovery is preferable here to merely changing to a different structured-output mode: the latter would change the model API surface, has no evidence of better performance with this provider, and still needs semantic validation. The original strict Function Calling remains acceptable if the error is returned to the model within a bounded new condition. A live cloud validation was not run, so robustness on the real endpoint and any TSR effect remain **not verified**. The exact opt-in condition IDs and isolated namespaces are in `configs/experiments/harness-v2-baseline-stabilization-v2.1.json`.
