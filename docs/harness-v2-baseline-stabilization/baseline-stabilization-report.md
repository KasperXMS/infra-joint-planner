# Baseline stabilization report

This branch analyzes the frozen `b7c1984` H1 36-cell Stage 2 experiment and H2 two-cell feasibility study. It does **not** change their traces, scores, method definitions, evaluator, Scheduler or Executor pool; it runs no new benchmark cells. Raw sensitive evidence remains on the experiment controller. Public [failure diagnostics](../../results/harness-v2-baseline-stabilization/failure-diagnostics-public.json) and [workflow features](../../results/harness-v2-baseline-stabilization/workflow-variation.json) are derived, redacted exports. Their scripts preserve trace-relative paths and response hashes for in-place verification.

| Finding | Evidence level | Consequence |
| --- | --- | --- |
| 11 Verifier calls supplied string `evidence_state_version`; 2 also violated status/candidate semantics. | Trace-supported observation | Strict rejection was correct; no silent coercion should be introduced. |
| Frozen `stop_on_first_tool`, `max_turns=1` and typed rejection produced fatal parse instead of corrective feedback. | Source-confirmed; deterministic SDK reproduction | A bounded retry can be tested as a new condition. It was not part of H1. |
| Leading-choice check and final terminal parser disagree on one saved LongBench candidate. | Reproduced defect | A separate terminal-feedback boundary removes the deterministic mismatch before native final selection. |
| 63 physical over-context requests were rejected explicitly. | Trace-supported observation | Context feasibility is observable; no silent truncation was found. |
| H2 bridge dispatches each one-action proposal immediately. | Source-confirmed behavior | Current tool surface cannot expose a useful pending suffix; a small explicit-fragment interface is needed for feasibility research. |
| Aware/Ledger lower aggregate costs but lower TSR than Blind. | Trace-supported observation | No quality-preserving cost claim or adapter Go decision follows. |

Blind's five incomplete cells comprise three raw-schema failures, one deterministic terminal-contract mismatch and one legitimate Manager-budget exhaustion. Four of five were stopped at a protocol or contract boundary; that is an upper bound on *potentially affected Completion*, not a prediction of recovered Completion or TSR. Candidate correctness is unknown. The model produced invalid protocol arguments, while the Harness failed to offer bounded correction and applied inconsistent terminal checks.

The code changes are deliberately separable. `harness-v2.1-terminal-contract-feedback` wraps the existing independent Verifier and adds no provider call, but changes Manager feedback for terminal-format mismatches. `harness-v2.1-bounded-verifier-protocol` preserves frozen semantic instructions and raw/semantic validation, but allows at most two Verifier provider attempts per decision; it changes request budget and can change decisions. `harness-v2.1-bounded-lookahead-scripted` is an offline planning-interface prototype; it is not wired into the live Manager and has no task result. Each has a distinct namespace and explicit unrun status in [v2.1 manifest](../../configs/experiments/harness-v2-baseline-stabilization-v2.1.json). None may be compared as if it were a frozen H1 Stage 2 score.

Focused deterministic verification: the real Agents SDK receives typed schema/semantic failure and can make one correction; a second invalid response stops within the cap. The terminal feedback and bounded-fragment state transitions have separate tests. Tests do not prove real cloud Verifier recovery probability or TSR. The historical Blind baseline remains 7/12 Completion, 3/12 TSR and should be described as protocol-censored in several cells, not retroactively “fixed.” The known cloud API spend remains the original receipt value; GPU monetary cost remains unknown.

Still unresolved are model-produced protocol reliability on the live endpoint, quality of completed wrong answers, evidence sufficiency in MultiHop/LongBench, and whether a live Planner uses explicit fragments without losing open-ended reasoning. A small preregistered new-condition study could address these; this branch has not executed one. Stage 3's prior No-Go is unchanged. Detailed evidence appears in [failure attribution](failure-attribution.md), [protocol analysis](verifier-protocol-analysis.md), [workflow variation](workflow-variation-analysis.md), [quality/cost analysis](quality-cost-failure-analysis.md), [anchor cases](anchor-case-studies.md), and [formal bridge diagnosis](formal-bridge-diagnosis.md).

Set `PYTHONPATH` to this checkout's `src` when running it, so `VerificationResult.model_json_schema()` comes from the frozen source rather than an older installed package. Its export is metadata-only; do not copy the private `stage2/cells/*/runs/*/trace.jsonl` or API response bodies to Git.
