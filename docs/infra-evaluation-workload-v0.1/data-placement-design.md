# Data placement policy

The assignment is independent of a task's gold answer. Every MultiHop article belongs to its original `source` publisher group; SHA256 of that stable group name chooses `source-a` or `source-b`. The complete 609-article corpus is installed as two per-node BM25 shards, with each original article also stored as its own immutable artifact on the same assigned node. This duplicate **within-node** representation is declared in the [residency manifest](manifests/source-residency.jsonl) and setup budget. It is not a hidden cross-node copy.

MultiModalQA's benchmark-provided candidate text contexts, including distractors, reside on `source-a`; candidate table contexts reside on `source-b`. The text/table partition is our **experimental modality-service architecture**. Original Wikipedia document IDs and content hashes are preserved. No document or video is split to manufacture Agents. The six retained questions and one excluded inspected question determine this bounded candidate-context deployment; a future full-corpus retrieval study must expand it before claiming general retrieval quality.

Artifact IDs, original source identity, logical source service, physical host and placement are separate fields. `source-a` is AGX Orin A4 (`192.168.0.104`, local `/mnt/ssd` ext4); `source-b` is the dual-4090 workstation (`192.168.0.12`, local `/dev/nvme0n1p2` ext4). The [manifest](manifests/source-residency.jsonl) records 438 / 248 resident artifacts and 7,949,758 / 5,381,773 logical source bytes respectively. SHA256-addressed `FileArtifactStore` filenames prevent path traversal and detect content drift on read. `index_version=none`: BM25 is computed from resident JSON on each query; no persistent retrieval index was created.

Cross-node copies made by the probe are listed in [transfer receipts](feasibility-public.json) and removed by [cleanup](cleanup-public.json). The 686 base source artifacts remain resident for a later authorized study. The experimental controller ran on the `source-b` host, which also has older MultiHop corpus copies in historical directories. Consequently, this deployment **does not enforce Controller/source-b filesystem isolation**. HTTP direct GET was denied, but an OS-level Controller process with that account can still access local source-b files. A separate Controller host or OS user/container with denied source mounts is required before a claim of complete data-locality enforcement or P2 readiness.
