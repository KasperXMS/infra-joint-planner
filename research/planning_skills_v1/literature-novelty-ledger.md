# Literature and novelty ledger

## Candidate decisions before new inference

1. **Reject broad novelty claims:** static granularity, dynamic disclosure, skill compilation, state ledgers, and cascading dependency invalidation all have close predecessors.
2. **Prioritize a bounded characterization:** under an identical strict tool contract, can generic procedural rules improve 4B/9B dependency execution and recovery, and does observation-only state projection alter that effect? Closest works: R2, R8 and PACMI; R3/R4 supply negative-effect explanations.
3. **Do not equate bookkeeping with planning:** the ledger contains no frontier, next action, chosen operation or private answer. It repeats only agent-visible artifact/value/validity/receipt data. The model still chooses source/tool, node, input order, numeric branch and termination.
4. **Novelty unresolved:** the expected deliverable can be reproducible characterization or a negative finding. A novel mechanism requires held-out evidence and a narrower distinction from the state-maintenance papers, not absence of a keyword in this reading list.

## Initial falsifiable hypotheses

- H1: static procedural rules improve valid workflow completion particularly when freshness changes require dependency rebuilding. An unchanged-source condition tests whether any gain is merely ordinary tool instruction.
- H2: local rule delivery changes overhead and failure behavior relative to the same full rule bank. It may lose useful recovery context; shorter is not presumed better.
- H3: an observation-only ledger reduces stale-handle/reconstruction errors beyond static rules. An added-length control is required if development suggests this benefit; semantic policy errors may remain unaffected.
- H4: capacity interacts with these mechanisms. A 4B/9B difference is conditional on these BF16 checkpoints and this backend, not a universal scaling law.
