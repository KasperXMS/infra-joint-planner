# Native Skill activation method and freeze

The phase-2 question is whether a short, generic instruction can induce the Agent to **use its own shell tool** to open relevant original `SKILL.md` files. The official Skill tree is byte-for-byte unchanged in S1, S2 and S3. S1 only advertises native Skill metadata; S2 additionally places the exact concatenated original bodies in Codex `developer_instructions`; S3 instead puts the read trigger in that same configuration slot. S3 contains no financial facts, answer, rewritten Skill, workflow, or hidden test information. Reading a Skill is scored only when a successful command returns its full original body and that body is visible in a later model request.

The first frozen trigger, [v1](read-trigger.txt), was 64 Qwen3.5-9B tokens (SHA-256 `e10bbf2a7cf79bb18de25c7252f54a1ba9fcbaa0a8f2915aa3216621e939e6b5`). Its one permitted old-development probe on `financial-analysis-2` received official reward 0: the trigger appeared in model requests, but neither main Skill was opened or present as a body in model context. The public [development receipts](evidence/development-probe-summary.json) summarize both probes; full traces remain private. The [v1 manifest](frozen-manifest.json) was frozen before that run (SHA-256 `277fe5b8643d2cfa2691b479de2bb7153d00b11bce8d84475408b14dbd4a4efb`); its planned validation cells were **not run**.

One prospective refinement was made before any `financial-analysis-4` model trial. The final S3 trigger is [v2](read-trigger-v2.txt), 68 Qwen tokens, SHA-256 `5e0da6c5ffd72e8b6132aa02d51d31e4fcfa38405072454af699f1f3f4a65803`:

> Required first step: Before inspecting task data or planning a solution, use the shell tool to read each relevant SKILL.md listed under Available skills. Resolve listed aliases using their root paths, then read the complete file. Treat metadata only as a pointer; do not proceed until the tool returns the full instructions. Read referenced scripts when needed.

The [v2 manifest](frozen-manifest-v2.json), SHA-256 `5da3f4ab8a4c4a7128ba1adac08952f311cb86c78c90161b59acf2a234b11594`, records the amendment, v1 receipt, exact trigger file/hash/token count, source and image hashes, model/Agent settings, budgets, seed limitation and balanced nine-cell validation order. No further trigger tuning is planned. v1 and v2 development probes remain separate from the new-instance validation denominator.

The runtime is the pinned Codex CLI 0.162.1 over Qwen3.5-9B BF16/vLLM 0.31.0, `responses` API, temperature 0, 16,384 context, 14,000 auto-compaction threshold, `reasoning_effort=none`, 900-second Agent budget and unchanged Docker task permissions. No reliable request seed control is exposed in this path; three fresh-container repetitions are independent executions but may still be highly correlated or identical. The original source verifier runs only after Agent exit, with tests and reference solution withheld from the Agent container. An official source oracle returned 1 for `financial-analysis-4`; an intentionally incomplete JSON artifact returned 0. The public [oracle and negative-control summary](evidence/oracle-preflight-summary.json) is backed by raw local receipts obtained before the new-instance model runs.
