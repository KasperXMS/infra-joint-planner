# Related-method boundaries (primary-source method review)

The phase-2 read trigger is an **activation baseline**, not a new compilation algorithm. The following papers materially narrow any future compiler novelty claim. Their methods, rather than just abstracts, were checked on 2026-10-14.

| Work | Actual mechanism | Overlap with a possible phase-2/phase-3 method | Boundary for this study |
|---|---|---|---|
| [SkVM](https://arxiv.org/html/2604.03088) | Profiles a model–harness pair against 26 primitive capabilities; extracts a Skill's requirements; applies capability-aware transforms, environment binding, concurrency extraction and runtime JIT optimization. Its compensation pass already makes instructions more explicit and strengthens constraints when the target is weaker. | Direct overlap with **model-aware Skill transformation**, capability profiling, strong-to-weak portability and runtime adaptation. | A generic `Trigger → Preconditions → Action → Check` rewriting scheme would be an incremental variant, not a distinct compiler. A future claim needs a verified failure mechanism and a controlled advantage over SkVM-style transformation on unseen instances. |
| [SkillSmith: Boundary-Guided Runtime Interfaces](https://arxiv.org/html/2605.15215) | Classifies Skill source shape, lowers it to a boundary contract, and executes the contract as a guarded state machine with blocked/guidance/execute paths, typed operators and a canonical result envelope. It can deoptimize to agent continuation. | Direct overlap with procedural IR, conditional guards, runtime verification, tool/script execution and recovery. | A guarded checklist or state-machine IR alone is **not novel**. Any proposal must show a distinct, narrower intervention, such as source-rule-specific repair of an observed small-model decision failure under unchanged tools and loading. Other unrelated papers also use the name SkillSmith; this row refers only to arXiv:2605.15215. |
| [SkillReducer](https://arxiv.org/html/2603.29919) | Optimizes routing descriptions with simulated-oracle delta debugging; classifies main-body content, keeps actionable core rules, moves other material to on-demand references, deduplicates and uses faithfulness/task quality gates. | Overlap with Skill discovery, progressive disclosure, compression, context cost and a length-controlled S4 baseline. | The present S3 does **not** rewrite descriptions or bodies; it merely asks the Agent to read the originals. A later compact Skill must be compared with SkillReducer and a length-matched original, not described as a novel compression method. |
| [SkillLens: From Raw Experience to Skill Consumption](https://arxiv.org/abs/2605.23899) ([project/code](https://microsoft.github.io/SkillLens/)) | Studies experience generation, model-generated Skill extraction and consumption across domains and target models; identifies failure-mechanism encoding, actionable specificity and high-risk action blacklists; prepends a compact meta-Skill to improve extraction. | Overlap with target-model heterogeneity and judging Skill utility by downstream outcome rather than textual quality. | Its primary intervention acts at **extraction of new Skills from experience**, while this phase preserves public human-authored originals and manipulates activation. If a later compiler adds failure-mechanism or checklist text, the overlap must be credited. The SkillLens name is also used by unrelated retrieval papers; this comparison names the Microsoft/Fudan study. |

The strongest defensible near-term question is **mechanistic evaluation**: when a native Skill is advertised but unread, can a 68-token generic trigger cause a genuine tool read and preserve official success on a predeclared new instance at lower repeated-context cost than verbatim injection? That is valuable as a controlled baseline, not a claim to have invented progressive disclosure. A compiler proposal is justified only if a loaded-original-Skill failure is tied to a reusable rule/branch/check and remains after runtime confounds are addressed; even then, SkVM and SkillSmith are substantive method baselines.
