# Loaded-Skill procedural-gap candidate screen

This is a **source and runtime screen**, not a claim that a zero score proves a compiler target. At most two new families will receive one oracle-checked development instance each; official Agent runs are limited to the WP3 budget. New task tests and references remain outside Agent containers. The predeclared development candidates below are not future held-out cases.

| Family and development instance | Reused original Skill rule | Validity/runtime concern | Screen decision |
|---|---|---|---|
| `offer-letter-generator-2` | `docx/SKILL.md` warns that placeholders may be split across Word XML runs and provides a robust paragraph-level replacement procedure (lines 10–76); it also gives a `{{IF_CONDITION}}…{{END_IF_CONDITION}}` keep/remove branch (around line 176). The task requires a final DOCX and a relocation conditional. | Could collapse into a straightforward template script; the task instruction itself states the conditional. An error is a Skill-specific procedural gap only if the body was loaded, the relevant source rule was applicable, and the trace shows that the Agent departed from it. | **Source reference passed the unchanged verifier (1).** One 9B loaded-original run is eligible; other family instances remain unused for future G2. |
| `court-form-filling-2` | `pdf/SKILL.md` directs form-filling users to `forms.md`; that reference requires checking whether a PDF has fillable fields before choosing the field-filling or annotation path and supplies validation steps. | The PDF may need visual interpretation unavailable to the text-only model; form-field mapping and a potentially large helper tree can cause context/tool confounds. A failure could be perception or document tooling, not procedural reasoning. | **Source reference passed the unchanged verifier (1).** One 9B loaded-original run is eligible; a later failure must be screened for perception/tooling confounds. |
| `dbscan-parameter-tuning-2` | Shared `custom-distance-metrics`, `parallel-processing`, `pareto-optimization` Skills; task asks for a Pareto frontier over a 7×11×11 hyperparameter grid and custom clustering distance. | The 847-combination search and scientific computation make time and arithmetic more likely bottlenecks than an isolated Skill-rule branch under a 900-second Agent budget. | Source-screened but not selected for the first two WP3 runs. |
| `weighted-gdp-calculation-3/-4` | Original `xlsx` Skill loaded in both prior 9B S2 runs. | Both time out with no changed workbook, 42/46 compaction warnings and repeated actions. 27B S1 was not loaded and later context-rejected. | Retain as runtime/execution case study; it is not clean compiler evidence. |
| `financial-analysis-2/-3` | Original 13F and fuzzy search Skills were verified in every prior S2 request and S2 scored 1 on both. | No residual loaded-Skill failure was observed on those two development cases. | Use for activation diagnosis only; new `-4` validation is separately frozen. |

The deciding case-study template is: source rule location → exact body in a model request → task state and observation → actual action → permissible alternative actions → artifact/verifier result → context/router/transport confounds. A single expected action sequence will not be imposed when multiple paths satisfy the official task.

The 9B S2 offer-letter diagnostic scored **1** on the official verifier despite an Agent timeout; the original DOCX main body was in every request. It is retained as an execution-efficiency case, not a binary failure. The 9B S2 court diagnostic scored **0** with the original PDF main body in all 55 requests, but the Agent never opened its referenced `forms.md`, 40 of 49 shell calls failed, and the output was a malformed zero-page PDF. The unchanged verifier could not extract text from that artifact. The predeclared 27B S2 court reference also scored **0**: it made a valid six-page PDF, but still did not read `forms.md`, failed required-content checks, and eventually hit a model context rejection. This pair is a resource-selection/tooling/runtime-confounded case, not evidence that a fully read form procedure was executed incorrectly by 9B alone.
