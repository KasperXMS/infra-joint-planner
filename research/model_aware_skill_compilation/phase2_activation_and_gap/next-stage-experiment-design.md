# Next-stage design is deferred by the compiler No-Go gate

The present evidence does not authorize a full S2/S4/S5 compiler comparison. S3 did not activate main Skills on the new financial instance; the loaded-original financial failure is a credible but single-instance candidate; and the new document-family observations are dominated by timeout or PDF/tool failures. A 32K service answered one synthetic long request, but a stable 32K Agent condition has not been evaluated.

The next study should first make native Skill activation measurable and reliable, then separately freeze a runtime/tool configuration that can complete longer tasks. It should prospectively reserve unseen instances of the financial family and an entirely unseen family, verify each source reference and negative scoring behavior before model runs, and retain every official-zero result including timeout and context rejection. A specific source-rule failure must recur with the original Skill actually present in model context and without dominant infrastructure confounds. Development cases used here (`financial-analysis-2/-3`, `offer-letter-generator-2`, `court-form-filling-2`) must never be relabeled as held out; `financial-analysis-4` is this phase's within-family validation and is also no longer unseen.

Only if that gate is met should a later protocol freeze original loaded Skill (S2), a length-matched/faithful compact original (S4), and source-traceable procedural intervention (S5) under identical model, harness, tools, inputs, verifier, loading and budget. It should distinguish development instances (G1), genuinely unseen instances of known families (G2), and entirely unseen families (G3). This conditional outline is **not** an approved experiment matrix or evidence that compilation helps. Capability-gap closure should be computed only if a loaded-Skill strong-model reference actually outperforms the small model on the same valid tasks.
