# Preliminary 9B development cases

These are official SkillsBench v1.1 **development** observations under the frozen configuration. One of eight 9B task pairs is complete; no held-out result or overall 9B treatment estimate is available yet. Original task verifiers determine binary resolution. Fractional reward and subtests explain failures but do not override the official outcome. Full trajectories, artifacts and requests remain private, with separate local backup.

## `dialogue-parser`, S0 No Skill

The original verifier assigned reward 0.167 and binary resolution **fail**. Its six top-level CTRF categories had one pass and five failures; the detailed pytest run passed 15 of 35 parameterized checks. The Agent reached the original 900-second wall-clock budget after 40 tool calls; BenchFlow completed scoring without a framework or verifier error. The Agent created JSON and DOT outputs: the verifier passed basic JSON/schema/file/graph-size checks but failed required narrative node IDs, graph edges and reachability, DOT choice-node shape, and expected content. This is an incomplete parser and graph artifact, rather than missing sandbox or evaluator execution.

The task result reports 1,017,803 prompt and 22,538 completion tokens from provider responses, 40 tool calls, and 957.2 seconds end-to-end. Its terminal timeout trajectory is complete, with no pending tool calls. Five ACP tool events have `failed` status, but three have `kind=other` and two `kind=think`; they are not five failed executable terminal actions. One generated response near timeout logged a `BrokenPipeError` while writing to the client, consistent with the Agent cancellation but not independently proof of its cause. No answer-based retry followed. A private AutoDL snapshot reconciles all 56 generations in this cell with the corresponding API prompt and completion token totals exactly; it also contains the earlier 4B cells and an excluded 9B identity probe. ## `dialogue-parser`, S1 Native Skill and paired interpretation

S1 also failed with official reward 0.167, one of six top-level CTRF categories passed, five failed, and no framework/verifier error. The detailed pytest checks differed: 21 passed and 14 failed. S1 retained more required narrative nodes and edges than S0, but missed `Start`, graph validity/reachability, DOT syntax/shape, and content checks. Both cells reached the same original 900-second Agent budget with complete terminal timeout trajectories and no pending tool calls. S0 → S1: 40 → 33 tool calls, 1,040,341 → 962,397 provider tokens, and 957.2 → 941.3 seconds end-to-end. These are descriptive differences from one greedy trial and neither binary resolution nor official fractional reward improved.

The S1 first model request contained the exact official Skill name in the native `<available_skills>` menu; the paired S0 request did not. S1 retained the original task-bundled Skill directory and reported zero harness invocations. The ACP screen found no native Skill file/reference read or bundled script execution in S1's complete trajectory. Thus this pair shows Skill availability without observed consumption, not evidence that the Skill content failed after use. Three S1 ACP events had `failed` status, but one was `kind=other` and two were `kind=think`; these are not three failed executable terminal actions. The S1 request log had no transport error.
