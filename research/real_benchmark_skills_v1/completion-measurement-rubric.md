# Completion evidence, separate from official task success

The original SkillsBench v1.1 verifier alone defines binary task resolution. These secondary measures describe where an Agent stopped; they do not replace the official reward or alter any task/verifier. Apply the same rules to S0 and S1, both models, and both frozen splits. Record `unknown` when the private trace or original verifier cannot support a judgment.

1. **Agent turn ended normally:** the original `result.json` has no Agent/API/framework error and the native ACP trajectory contains a final `agent_message`. A wall-clock or idle timeout is `false`, even if the original verifier subsequently scores a partial artifact. This measures turn termination, not task completion.
2. **Required output artifact delivered:** the artifacts explicitly required by the original `task.md` exist in the solver's output at verifier time. Use the original verifier's existence/import/structure checks and preserved private artifact evidence. When a task has multiple required outputs, all must be present; a file at the wrong path is absent for this measure. An empty or malformed required file can count as present but fail the next stage. If the task is answer-only or the verifier does not expose enough evidence, report `not_applicable` or `unknown` with a reason, rather than inferring delivery from normal termination.
3. **Substantive artifact validity:** report original verifier format, import, schema and task-specific content checks by name, without collapsing heterogeneous checks into a universal success score. A delivered artifact can fail correctness, graph reachability, domain classification, or execution checks. The official binary result remains the primary metric.
4. **Recovery after a failed operation:** identify the failed command/tool step, an observable corrective action, and verifier-relevant progress in the original trajectory. A repeated lookup or a later normal Agent message alone is insufficient. Report only trace-supported cases, not a global recovery rate when opportunity definitions differ across tasks.

For paired comparison, show S0 and S1 side by side for these stages, tool/terminal errors, Skill delivery/read/execution, tokens and wall time. Treat the artifact and workflow stages as descriptive because the 24 official tasks have different output contracts. A Skill menu in the first model request is availability, not consumption; a Skill file read is consumption evidence, not proof of application. One greedy trial per cell cannot establish that Skill availability caused a stage difference. The development set may inform a mechanism decision; held-out task outcomes remain unseen until that decision and its configuration are frozen.
