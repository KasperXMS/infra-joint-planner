# Preliminary development cases: first seven 4B task pairs

These are official SkillsBench v1.1 **development** cells under the frozen configuration. They are not a held-out estimate or a claim that Skills cannot help. The original verifiers ran without framework or verifier errors. The primary outcome is binary task resolution; fractional reward and verifier subtests are explanatory only. Full trajectories, artifacts and requests remain in the private workspace and its separate local backup. For `dialogue-parser`, both cells passed five of six verifier checks and failed `test_visualization_validity` at the diamond-shape check. The untouched [official verifier](https://github.com/benchflow-ai/skillsbench/blob/b63b7b2850226b6aa4fb5929a8c1ac7bc4d9a6af/tasks/dialogue-parser/verifier/test_outputs.py#L187-L190) requires choice nodes to use diamond shapes. This is an artifact completeness failure, not evidence of a tool API or sandbox failure. The extra S1 cost without a read action is evidence of Skill availability not turning into observed consumption in this cell; one pair cannot establish why the model did not read it.

For `azure-bgp-oscillation-route-leak`, both cells passed output structure, oscillation detection and leak detection checks, then failed `test_solution_classification`. The [official verifier](https://github.com/benchflow-ai/skillsbench/blob/b63b7b2850226b6aa4fb5929a8c1ac7bc4d9a6af/tasks/azure-bgp-oscillation-route-leak/verifier/test_outputs.py#L90-L104) checks each proposed mitigation's two resolution flags. In the captured failures, S0 marked a leak as unresolved when the oracle expectation was true; S1 marked an oscillation as unresolved when the expectation was true. Detection reached a valid intermediate stage, yet the final domain decision remained wrong. The official task reward is zero for both despite those passing subtests.

For `econ-detrending-correlation`, both cells failed `test_answer_file_exists`; the three tests dependent on that file were skipped. S0 reached the original 900-second Agent budget after 35 tool calls, with a complete timeout trajectory and no pending tool action. S1 made 55 tool calls and ended its turn without a timeout, yet still did not produce the required answer file. ACP marks eight S1 `think` events (steps 42, 51, 61, 63, 65, 67, 69, 71) as failed; these are not eight failed executable terminal actions. This pair distinguishes termination behavior from successful artifact delivery. It does not show that Skill availability caused the termination change: no Skill read action was observed in S1, and there is one greedy trial per condition.

For `crystallographic-wyckoff-position-analysis`, S0 ended its turn after exploratory CIF and library calls without producing `solution.py`; the original verifier could not import `solution` and assigned its documented default score of zero. S1 produced an importable solution, but the original verifier accepted only four of eleven CIF cases (reward 0.36), so binary resolution remained a failure. Among terminal calls with a reported exit status, S0 had 14 nonzero exits in 29 calls and S1 had 3 in 21; these include exploratory commands and are not by themselves the official outcome. The S1 trace contains no observed native Skill file read or harness invocation. The artifact difference is descriptive and cannot be attributed to Skill consumption from this single pair.

For `adaptive-cruise-control`, both cells reached the official 1,800-second Agent wall-clock limit. The original verifier accepted two of twelve S0 checks and three of twelve S1 checks; the extra S1 pass was `test_report_keywords`, while the substantive control/simulation checks failed in both cells. Both official rewards and binary resolutions were zero. At timeout, S0 had three pending ACP calls and S1 had four; neither terminal trajectory is complete. No native Skill read appeared in the captured S1 actions, which does not establish that no later pending action could have used one. End-to-end time includes a 153.9-second S0 environment setup versus 41.1 seconds for S1, so the shorter S1 wall time is not evidence of a Skill efficiency gain. The original verifier ran without framework error in both cells.

For `court-form-filling`, both cells failed to create the required `/root/sc100-filled.pdf`. The original verifier's fixture therefore reported the missing output across its parameterized checks; BenchFlow recorded no framework or verifier error, and the official reward was zero in both cells. S0 reached the task's 1,800-second Agent budget with a complete terminal trajectory and no pending action. S1 ended normally after fewer tool calls, but still did not deliver the PDF. The captured S1 trace includes no native Skill path read. An earlier path/name screen falsely marked a read of `/root/sc100-blank.pdf` as access to the `pdf` Skill; manual inspection disproved that hit, and the screen now requires a native Skill path. The shorter S1 run and different termination cannot be attributed to Skill use from this single pair. Original verifier stdout SHA256: S0 `1117971cf01bf9421082dbb3f46dce1cfd509428c92b3399494b00e1fdc27671`, S1 `d9ee61abd550a1ae93e26cf1da5611c4c568cbf9cfff07221ce2a2ad8bec0fd7`.

One S0 model response was generated near timeout, then the relay logged `BrokenPipeError` while writing it to a disconnected client. Its 25,071 prompt and 1,040 completion tokens appear in the private API response and AutoDL backend counters but not in the Agent's received-usage total; they remain included in actual inference workload. The timing is consistent with Agent cancellation at timeout, though the disconnect cause is not proven. No answer-based retry or re-scoring followed.

For `dapt-intrusion-detection`, both cells reached the original 600-second Agent budget without filling the required `network_stats.csv` values. The untouched verifier reported 37 missing or incorrect metric/flag checks in each cell and assigned reward zero. S0 ended with one pending ACP action and an incomplete terminal trajectory; S1 had a complete timeout trajectory with no pending action. The S1 trace shows no native Skill path read or harness invocation. The apparent reduction in end-to-end time includes 138.5 seconds of S0 environment setup versus 24.1 seconds for S1; it cannot establish a Skill speed effect. BenchFlow's aggregate summary displays zero tokens for these timeout cells, while each task's `result.json` contains the provider-reported usage stated in the table. The original verifier ran without framework error in both cells.
