# Development analysis working notes (26/32 cells)

This is an **incomplete development-stage draft**, not the frozen analysis or a held-out estimate. It covers 13 matched tasks across model sizes as of the 26th completed original SkillsBench v1.1 cell. The other six development cells and every held-out cell are excluded. Original verifier resolution is the primary outcome; fractional reward, subtests, trajectories, and timing are explanations only. The authoritative cell-by-cell record is under the private WSL jobs directory, with separately hashed local archives. Public case evidence is indexed in `development-case-notes.md` and `development-9b-case-notes.md`.

## Observed outcome and delivery

All 26 completed cells have official binary resolution **fail**: eight 4B S0/S1 pairs and five 9B S0/S1 pairs. This is a development observation with a floor effect, not an estimate for the held-out set or evidence that Skills never help. Some tasks have partial original-verifier credit. For example, 4B crystallography S1 reached 4/11 examples and 9B S1 reached 8/11, while neither passed the full task. Their complete trajectories show no native Skill file read, so this is not evidence that Skill contents caused the partial improvement.

The first-request audit confirms the exact official native Skill names in all 13 S1 model system messages and none in the 13 paired S0 messages. The completed ACP path/action screen finds a native Skill content read only in 4B Civ6 S1, where the Agent opened `SKILL.md` and bundled rules but never delivered the required JSON. No direct bundled Skill-script launch is currently detected. `n_skill_invocations` is zero in all 13 S1 cells. These are observations about recorded actions: the screen can miss indirect access, and a menu mention does not prove attention or use.

## Provisional failure factors

| Skill available but not observably consumed | The Skill menu reached 13/13 S1 first requests, but only 4B Civ6 S1 has a confirmed native file read. 9B cruise-control S1 had all five Skill names offered and zero native read candidates, then failed with undefined `PIDController` and missing output files. | This establishes a delivery-to-use gap in the recorded sample, not why the model did not open Skills or that a Skill read would have solved the task. |
| Skill read without task completion | 4B Civ6 S1 read the official Skill and rules twice, then repeatedly inspected rules without producing the required JSON. | Reading is weaker than correct application; the trace does not demonstrate a successful executable Skill interface. |
| Transport error at timeout | Court 4B S0 and cruise-control 9B S1 each have a response-write `BrokenPipeError` near an Agent timeout. Generated tokens are retained in API and backend cost counters. | A disconnected response near cancellation is not itself proof of the cause, and these events do not warrant answer-based reruns. |

The original verifier and sandbox ran normally for these 26 cells. Provisional factors can coexist in one task. Do not label ACP `think` failures as executable tool errors or count an exploratory nonzero shell exit as a final task failure without reviewing the private action span. The exact-adjacent repetition screen currently finds 13 extra actions in five cells; it is a lower-bound candidate screen, not an automatic count of failed recovery.

## Method gate still open

Skill discovery/consumption is a plausible bottleneck, but a better Skill menu, progressive disclosure, routing, structured procedure, or executable interface overlaps published SkillsBench-adjacent work. `related-work-boundaries.md` records the primary-source boundary for SkillLens, SkillReducer, SkillSmith, SkVM, granularity, SkillCraft, and Agent Workflow Memory. The complete 32-cell development analysis must establish both a specific failure mechanism and a fair, literature-distinct candidate with finite development validation before any S2 is frozen. A relabeled compiler/router or a task-specific oracle-derived shortcut would not meet the brief. If no candidate passes that gate, explicitly omit S2 and run the full 64-cell held-out S0/S1 comparison.

At 32/32, regenerate the complete official result, trace, Skill visibility, repetition, paired, Skill-use, tool-error, backend-reconciliation, and cost reports. Inspect task-level artifacts and failures, write the final `development-analysis.md` and `development-method-decision.json`, and run `freeze_development_analysis.py`. Its receipt must exist before the held-out runner starts. This draft alone is insufficient to open evaluation.
