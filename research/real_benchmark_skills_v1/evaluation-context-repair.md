# Held-out context-budget amendment after an unscored ACP fault

The seventh formal held-out attempt, `evaluation-4b-sec-financial-report-s1-t1`, ended with BenchFlow `acp_error` and no original verifier run. Its official `rewards` field is `null`; the original summary has `errored=1`, `passed=0`, `failed=0`, and `verifier_time_sec=0`. It is **not** a model task failure or a result in the 64-cell denominator. The Agent had already made 38 tool calls and 86 successful model calls; two later model calls returned HTTP 400 `context_length_exceeded`. The backend counted 28,940 and 28,726 input tokens respectively, which exceed the 32,768 context when combined with the requested 4,096 output-token cap. The ACP session then failed before scoring.

The full attempt, its 89 private request-status records (88 model calls and one status record), its batch and handoff logs, and its 6,020,055-byte private archive are preserved under `excluded/infrastructure-attempts/evaluation-4b-sec-financial-report-s1-t1-context-overflow-acp-fault-1791914280/` in WSL and the matching private backup directory. Archive SHA256: `1f5e4d00d1c96451044f00b7ae35516999c583ea18b954bc5fdbd519127a8770`. The attempt was removed from the active run and request namespaces before a new official cell could use the same frozen run ID. The first six valid held-out cells and their verified archives were left untouched.

The repair has two uniform, task-independent safeguards. OpenHands now receives `max_input_tokens=28000`, below the physical input ceiling of 32,768 − 4,096 = 28,672, while its requested output cap remains 4,096. The pinned inference server retains the 32,768 context and 4,096 maximum but bounds each actual generation to `min(requested_output_tokens, 32768 − exact_input_tokens)` after tokenization. The server logs the requested and effective cap and whether this safeguard was used. It still rejects inputs that alone exceed the context, output requests above 4,096, and non-greedy decoding. No task, Skill, oracle, verifier, model weight, tool permission, task budget, or answer-based retry policy changed.

Before the repair, the six valid held-out cells' maximum API prompt sizes were 26,678, 26,810, 26,849, 24,891, 26,808 and 26,598 tokens. None would have needed output clamping. Both conditions of each of those three task pairs used the old settings. All remaining task pairs, including both valid `sec-financial-report` conditions, use the revised settings; no already scored cell is rerun. This prospective change creates a configuration epoch boundary across tasks. Paired S0/S1 comparisons stay within one epoch, but the final report must disclose the boundary when pooling tasks, and cannot claim every held-out cell used identical context handling. The unscored SEC attempt's consumed tokens and rental time remain part of resource accounting, outside success-rate denominators.

The revised OpenHands launch passed the pinned adapter's shell syntax and receipt checks. The resumed official SEC sandbox's live settings file showed `max_input_tokens=28000` and `max_output_tokens=4096` for both the main Agent and its same-model condenser. A synthetic API call containing 28,818 input tokens requested 4,096 output tokens and returned HTTP 200; the generation record shows an effective cap of 3,950 and `context_clamped=true`, with two completion tokens used. This compatibility probe used no benchmark task content and is excluded from formal results. The model service was restarted only after confirming it was idle; the AutoDL instance was not stopped. [Machine-readable amendment](evaluation-context-amendment.json), preserved pre-repair config/source files, and private deployment receipts provide exact hashes.
